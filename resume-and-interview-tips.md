## Resume Writing

### General Principles

1. **Length**: One page for <10 years experience, two pages maximum for 10+ years
2. **Format**: PDF format (preserves formatting across systems)
3. **Font**: Professional fonts (Calibri, Arial, Helvetica) at 10-12pt
4. **Sections**: Clear section headers with consistent formatting
5. **ATS-Friendly**: Avoid tables, graphics, headers/footers (they confuse Applicant Tracking Systems)

### Content Strategy

#### Use Action Verbs

Start bullet points with strong action verbs:

**Technical Actions**:
- Architected, Designed, Developed, Engineered, Implemented
- Built, Created, Programmed, Coded, Refactored
- Optimized, Improved, Enhanced, Modernized
- Debugged, Troubleshot, Resolved, Fixed

**Leadership Actions**:
- Led, Managed, Coordinated, Mentored, Coached
- Spearheaded, Initiated, Launched, Established
- Collaborated, Partnered, Facilitated

**Impact Actions**:
- Increased, Reduced, Accelerated, Improved
- Delivered, Achieved, Completed, Accomplished
- Scaled, Expanded, Streamlined

#### Quantify Your Impact

Always include numbers to demonstrate impact:

```
❌ Improved application performance
✅ Improved application performance by 40%, reducing page load time from 3.2s to 1.9s

❌ Led a team of developers
✅ Led team of 5 developers to deliver 3 major features in Q2 2024

❌ Reduced bugs in production
✅ Reduced production bugs by 60% (from 50 to 20 per month) through automated testing

❌ Worked on microservices migration
✅ Migrated monolithic application (500K LOC) to 12 microservices, improving deployment frequency from monthly to daily
```

#### STAR Format for Accomplishments

**S**ituation - **T**ask - **A**ction - **R**esult

```
Example:
"Redesigned payment processing system (Situation) to handle Black Friday traffic
(Task) by implementing distributed caching and horizontal scaling (Action),
supporting 10K transactions/second with 99.99% uptime (Result)"
```

### Common Mistakes to Avoid

1. **Too Generic**
   - ❌ "Responsible for developing features"
   - ✅ "Developed 15+ user-facing features using React and TypeScript, increasing user engagement by 25%"

2. **Missing Context**
   - ❌ "Used Python and Django"
   - ✅ "Built REST API with Django serving 1M+ daily requests for mobile app with 500K MAU"

3. **No Impact**
   - ❌ "Wrote unit tests"
   - ✅ "Increased code coverage from 45% to 85%, reducing production bugs by 50%"

4. **Irrelevant Information**
   - Remove: High school information, outdated skills (Flash, FrontPage), personal hobbies unrelated to tech

5. **Typos and Grammar**
   - Proofread multiple times
   - Use Grammarly or similar tools
   - Have someone else review

## Resume Sections

### 1. Header

**Include**:
- Full name (larger font, bold)
- Phone number
- Professional email (firstname.lastname@gmail.com)
- LinkedIn URL
- GitHub URL
- Personal website/portfolio (optional)
- Location (City, State - no full address needed)

**Example**:
```
JOHN DOE
San Francisco, CA | (555) 123-4567 | john.doe@gmail.com
linkedin.com/in/johndoe | github.com/johndoe | johndoe.dev
```

**Don't Include**:
- Photo (US standard, may cause bias)
- Age, marital status, nationality
- Full street address
- Multiple phone numbers or emails

### 2. Summary/Objective (Optional)

Use only if you're changing careers or have unique value proposition. Otherwise, skip it.

**Good Summary**:
```
"Senior Full-Stack Engineer with 8+ years building scalable web applications.
Specialized in React, Node.js, and AWS. Led 3 teams to deliver products serving
10M+ users. Seeking Principal Engineer role to drive technical strategy."
```

**Bad Summary**:
```
"Passionate developer seeking challenging opportunities to grow my skills
and contribute to innovative projects."
```

### 3. Skills

**Organization Options**:

**Option 1: By Category**
```
Languages: JavaScript, TypeScript, Python, Java, C#, SQL
Frontend: React, Redux, Next.js, Vue.js, HTML5, CSS3, Tailwind
Backend: Node.js, Express, Django, .NET Core, Spring Boot
Databases: PostgreSQL, MongoDB, Redis, DynamoDB
Cloud/DevOps: AWS (EC2, S3, Lambda, RDS), Docker, Kubernetes, CI/CD
Tools: Git, JIRA, Webpack, Jest, Linux
```

**Option 2: By Proficiency**
```
Proficient: JavaScript, React, Node.js, PostgreSQL, AWS, Docker
Familiar: Python, Django, MongoDB, Kubernetes, GraphQL
```

**Tips**:
- List 10-20 relevant skills
- Prioritize skills in job description
- Be honest - only list skills you can discuss in depth
- Remove outdated technologies unless relevant
- Use specific versions/frameworks (React vs "JavaScript frameworks")

**Format**:
```

• Accomplishment with metrics and impact

**Example**:
```

  reducing API latency by 60% (from 500ms to 200ms)

**Tips**:
- 3-5 bullet points per role
- Focus on recent roles (last 5-7 years)
- Older roles can be condensed to 1-2 bullets
- Show progression (Junior → Mid → Senior)
- Include promotions prominently

### 5. Projects (Optional for experienced developers)

Use if you:
- Are early career with limited work experience
- Have impressive side projects or open source contributions
- Want to showcase different tech stack than current job

**Format**:
```

Brief description of what the project does
• Key feature or technical challenge overcome
• Impact or usage statistics if available
• Link to GitHub/demo
```

**Example**:
```
REAL-TIME CHAT APPLICATION | React, Socket.io, Node.js, MongoDB    2024
Built scalable real-time messaging platform supporting 1,000+ concurrent users
• Implemented WebSocket connections with Socket.io for instant message delivery

```

### 6. Education

**Format**:
```
UNIVERSITY NAME                                 City, State
Degree, Major                                   Graduation Year
GPA: X.XX/4.0 (if > 3.5)                        Relevant Coursework (optional)
```

**Example**:
```
STANFORD UNIVERSITY                             Stanford, CA
Bachelor of Science, Computer Science          2020
GPA: 3.8/4.0
Relevant Coursework: Algorithms, Operating Systems, Machine Learning,
Databases, Distributed Systems
```

**Tips**:
- List most recent/highest degree only
- Remove GPA if < 3.5 or graduated > 5 years ago
- Remove graduation year if > 10 years (reduces age discrimination)
- Include relevant coursework if early career
- List honors, awards, scholarships if impressive

### 7. Certifications (Optional)

List if:
- Relevant to position (AWS Certified, Google Cloud Professional)
- Recent (< 3 years old)
- Recognized in industry

**Example**:
```
AWS Certified Solutions Architect – Professional    2024
Certified Kubernetes Administrator (CKA)            2023
```

### 8. Awards and Achievements (Optional)

Include if impressive:
- Hackathon wins
- Technical competitions
- Patents
- Published papers
- Open source contributions to major projects

## Interview Preparation Timeline

### 3 Months Before

**Week 1-2: Assessment and Planning**
- [ ] Review job descriptions for target roles
- [ ] Identify skill gaps
- [ ] Create study schedule (15-20 hours/week)
- [ ] Gather resources (books, courses, practice platforms)

**Week 3-6: Foundations**
- [ ] Data Structures: Arrays, Linked Lists, Stacks, Queues, Hash Tables
- [ ] Algorithms: Sorting, Searching, Recursion
- [ ] Time/Space Complexity Analysis
- [ ] Easy problems on LeetCode/HackerRank (50+)

**Week 7-10: Intermediate Topics**
- [ ] Trees and Graphs (DFS, BFS, Binary Search Trees)
- [ ] Dynamic Programming basics
- [ ] Medium problems (30+)
- [ ] System design fundamentals

**Week 11-12: Advanced Topics**
- [ ] Advanced DP, Greedy Algorithms
- [ ] Graph algorithms (Dijkstra, Topological Sort)
- [ ] Hard problems (10+)
- [ ] Mock interviews

### 1 Month Before

**Week 1-2: Focused Practice**
- [ ] Company-specific practice (search "[Company] interview questions")
- [ ] Review common patterns
- [ ] Daily practice (2-3 problems)
- [ ] System design case studies (for senior roles)

**Week 3-4: Interview Readiness**
- [ ] Mock interviews with peers or Pramp/interviewing.io
- [ ] Behavioral question preparation (STAR method)
- [ ] Resume final review
- [ ] Research companies thoroughly

### 1 Week Before

**Final Preparation**
- [ ] Review fundamental concepts (don't learn new topics)
- [ ] Practice easy/medium problems for confidence
- [ ] Review your resume and projects in depth
- [ ] Prepare questions to ask interviewers
- [ ] Test technical setup (camera, mic, internet)
- [ ] Get adequate sleep

### Day Before

- [ ] Light review only (don't cram)
- [ ] Prepare interview space (quiet, professional background)
- [ ] Charge devices, test backup laptop/phone
- [ ] Lay out professional attire
- [ ] Relax and get good sleep

### Day Of

- [ ] Eat a good meal 2 hours before
- [ ] Arrive 10-15 minutes early (or login early for virtual)
- [ ] Have water nearby
- [ ] Bring pen and paper for notes
- [ ] Turn off notifications
- [ ] Breathe and stay confident

## During the Interview

### Technical Interview Best Practices

#### 1. Problem-Solving Communication

**Do**:
- ✅ Think out loud: "I'm considering two approaches..."
- ✅ Ask clarifying questions: "Can the array be empty?"
- ✅ Explain your reasoning: "I'm using a hash map because..."
- ✅ Discuss trade-offs: "This uses more memory but is faster..."

**Don't**:
- ❌ Silent coding for 10 minutes
- ❌ Jump to code immediately
- ❌ Ignore the interviewer's hints
- ❌ Get defensive about feedback

#### 2. Structured Approach

Follow the UMPIRE method (see [Problem-Solving Framework](./problem-solving-framework.md)):

1. **Understand** the problem
   - Restate in your own words
   - Ask clarifying questions
   - Work through examples

2. **Match** to patterns
   - "This seems like a two-pointer problem..."
   - Identify relevant data structures

3. **Plan** your solution
   - Outline approach before coding
   - Discuss time/space complexity
   - Get interviewer buy-in

4. **Implement** cleanly
   - Write readable code
   - Use good variable names
   - Handle edge cases

5. **Review** your code
   - Walk through test cases
   - Check for bugs
   - Consider optimizations

6. **Evaluate** complexity
   - State time/space complexity
   - Discuss potential improvements

#### 3. Handling Difficulty

**If you're stuck**:
1. Don't panic or give up
2. Talk through what you're thinking
3. Break the problem into smaller parts
4. Ask for a hint: "I'm stuck on X. Can you give me a hint?"
5. Try a simpler version first
6. Look for patterns from similar problems

**Example**:
```
"I'm thinking this might be a dynamic programming problem, but I'm not
sure how to define the subproblems. Could I start with a brute force
approach and then optimize?"
```

#### 4. Code Quality

Even under pressure:
- Use meaningful variable names (`count`, not `x`)
- Add comments for complex logic
- Handle edge cases explicitly
- Keep functions focused and small
- Write code you'd be proud to review

**Bad**:
```python
def f(a, t):
    d = {}
    for i in range(len(a)):
        c = t - a[i]
        if c in d:
            return [d[c], i]
        d[a[i]] = i
```

**Good**:
```python
def two_sum(nums, target):
    """Find two numbers that sum to target."""
    # Hash map to store number -> index
    seen = {}

    for i, num in enumerate(nums):
        complement = target - num

        # Check if complement exists
        if complement in seen:
            return [seen[complement], i]

        seen[num] = i

    return []  # No solution found
```

### Behavioral Interview Best Practices

#### 1. STAR Method

Every behavioral answer should follow **Situation**, **Task**, **Action**, **Result**:

**Question**: "Tell me about a time you had to debug a difficult issue."

**Bad Answer**:
```
"I debugged a production issue once. It was hard but I figured it out."
```

**Good Answer**:
```
"In my last role [Situation], our API was experiencing random timeouts
affecting 5% of requests, causing customer complaints [Task]. I added
detailed logging to track request lifecycle, analyzed patterns, and
discovered database connection pool exhaustion due to connections not
being properly released in error cases [Action]. I implemented try-finally
blocks for cleanup, added connection pool monitoring, and documented the
fix for the team. Timeout rate dropped to 0.1% and we caught two similar
issues early using the new monitoring [Result]."
```

#### 2. Common Behavioral Questions

**Prepare 8-10 stories covering**:
- Technical challenge you solved
- Conflict with teammate
- Leadership/initiative
- Failure and what you learned
- Learning something new quickly
- Receiving/giving feedback
- Working under pressure
- Helping others/mentoring

See [Behavioral Questions Guide](./behavioral/mid-level.md) for more examples.

#### 3. Asking Questions

**Always prepare 5-7 questions** for the interviewer. Shows interest and helps you evaluate the company.

**Good Questions**:

*About the Role*:
- "What does success look like in this role in the first 6 months?"
- "What are the biggest technical challenges the team is facing?"
- "How is the team structured and how do you collaborate?"

*About Technology*:
- "What's your tech stack and why did you choose it?"
- "How do you handle technical debt?"
- "What's your approach to testing and code quality?"

*About Culture*:
- "How do you support professional development?"
- "What's the on-call rotation like?"
- "How do you balance feature development with maintenance?"

*About Growth*:
- "What are the career progression paths here?"
- "How do you handle performance reviews?"
- "What opportunities are there for learning new technologies?"

**Avoid**:
- Questions answered on the company website
- Salary/benefits in early rounds (save for offer stage)
- "What does your company do?" (shows lack of research)

## After the Interview

### Immediate Follow-up (Within 24 hours)

**Send Thank-You Email**:

```
Subject: Thank you - [Your Name] - [Position] Interview

Dear [Interviewer Name],

Thank you for taking the time to speak with me today about the [Position]
role at [Company]. I enjoyed learning about [specific topic discussed] and
discussing [specific technical challenge or project].

Our conversation reinforced my excitement about the opportunity to
[contribute to specific team/project]. I'm particularly interested in
[something specific that resonates with you].

Please don't hesitate to reach out if you need any additional information.
I look forward to hearing about the next steps.

Best regards,
[Your Name]
```

**Tips**:
- Keep it brief (3-4 sentences)
- Reference specific topics discussed (personalizes it)
- Reiterate your interest
- Send to each person you interviewed with

### Waiting Period

**Timeline expectations**:
- Phone screen follow-up: 3-5 days
- Onsite follow-up: 1-2 weeks
- Offer: 1-3 weeks after final interview

**What to do while waiting**:
- Continue interviewing elsewhere (don't put all eggs in one basket)
- If 1 week past expected timeline, send polite check-in email
- Don't send multiple follow-ups
- Keep applying to other positions

**Check-in Email** (after 1 week):
```
Subject: Following up - [Your Name] - [Position] Interview

Hi [Recruiter Name],

I wanted to follow up on my interview for the [Position] role on [Date].
I remain very interested in the opportunity and would love to know if
there are any updates on the hiring timeline.

Please let me know if you need any additional information from me.

Thank you,
[Your Name]
```

### Handling Rejections

**Stay Professional**:
```
Thank you for letting me know. While I'm disappointed, I appreciate the
opportunity to interview with [Company]. If there are other positions that
might be a better fit in the future, I'd love to stay in touch.
```

**Ask for Feedback** (they may or may not provide it):
```
I'd appreciate any feedback you could share about my interview performance
to help me improve for future opportunities.
```

**Learn and Move On**:
- Don't take it personally
- Reflect on what to improve
- Apply lessons to next interview
- Keep applying

## Negotiation Tips

### Before Negotiating

**Research**:
- Use levels.fyi, Glassdoor, Blind for salary data
- Know your market rate based on:
  - Location
  - Years of experience
  - Company size/stage
  - Skill set
- Understand total compensation:
  - Base salary
  - Bonus/equity
  - Benefits (health, 401k, PTO)
  - Perks (WFH, learning budget, relocation)

**Preparation**:
- Know your minimum acceptable offer
- Have competing offers if possible (major leverage)
- Prepare justification for your ask

### The Offer

**Initial Response**:
```
✅ "Thank you for the offer! I'm excited about the opportunity. I'd like
some time to review the details. When do you need my response?"

❌ "I accept!" (before reviewing or negotiating)
❌ "That's lower than I expected." (negative tone)
```

**Buy Time**:
- Ask for offer in writing
- Request 3-7 days to review
- Use this time to:
  - Get competing offers
  - Evaluate total compensation
  - Prepare negotiation strategy

### Negotiation Strategy

**Email Template**:
```
Subject: [Your Name] - [Position] Offer Discussion

Hi [Recruiter/Hiring Manager],

Thank you again for the offer. I'm very excited about joining [Company]
and contributing to [specific team/project].

I've reviewed the offer details, and I'd like to discuss the compensation
package. Based on my [X years of experience], [specific skills/expertise],
and [market research/competing offers], I was hoping for a base salary in
the range of $[X] - $[Y].

Additionally, I'd like to discuss:
• [Equity amount]
• [Signing bonus]
• [Remote work flexibility]
• [Other benefits]

I'm confident we can find a package that reflects the value I'll bring to
the team. I'm happy to discuss this further. Are you available for a call
this week?

Looking forward to working together.

Best,
[Your Name]
```

**Negotiation Do's**:
- ✅ Be enthusiastic about the role
- ✅ Provide justification (market data, competing offers, specific skills)
- ✅ Be specific with numbers ("$X" not "more money")
- ✅ Negotiate multiple components (base, equity, bonus, benefits)
- ✅ Be respectful and professional
- ✅ Ask "Is there any flexibility on..." rather than demanding

**Negotiation Don'ts**:
- ❌ Lie about competing offers
- ❌ Be aggressive or entitled
- ❌ Focus only on money (mention excitement about role)
- ❌ Negotiate before receiving written offer
- ❌ Accept immediately then try to renegotiate

### Common Negotiation Tactics

**Competing Offers**:
- Most powerful leverage
- Be honest, don't lie
- "I have another offer at $X, but I prefer your company because..."

**Market Data**:
- "Based on levels.fyi, the market rate for this role is..."
- Show your research
- Less powerful than competing offers but still valid

**Specific Value**:
- "Given my expertise in [rare skill] and [specific achievement], I believe..."
- Justify based on unique value you bring

**Total Compensation**:
- If base salary is fixed, negotiate:
  - Signing bonus
  - Equity
  - Performance bonus
  - Remote work
  - Professional development budget
  - Earlier performance review

### Response to Counter-Offer

**If They Meet Your Ask**:
```
"Thank you! I'm excited to accept and join the team. When should I plan
to start?"
```

**If They Come Up But Not Fully**:
```
"I appreciate you working with me on this. Is there any additional
flexibility on [component], or could we explore [alternative like signing
bonus, equity, earlier review]?"
```

**If They Don't Budge**:
```
"I understand. Let me take a day to think it over and I'll get back to
you tomorrow."

Then decide:
- Accept if it's still good
- Decline if it's below your minimum
- Ask for other benefits if salary is fixed
```

### Final Acceptance

```
Subject: Offer Acceptance - [Your Name] - [Position]

Dear [Hiring Manager],

I'm delighted to accept the offer for the [Position] role at [Company].
I'm excited to join the team and contribute to [specific goal/project].

As discussed, the offer details are:
• Start Date: [Date]
• Base Salary: $[X]
• Equity: [X shares/options]
• [Other components]

Please let me know the next steps for onboarding. I look forward to
starting on [date].

Best regards,
[Your Name]
```

## Summary Checklist

**Resume**:
- [ ] One page (or two for 10+ years experience)
- [ ] ATS-friendly format (no tables/graphics)
- [ ] Quantified accomplishments with metrics
- [ ] Action verbs starting each bullet
- [ ] Relevant skills matching job descriptions
- [ ] No typos or grammar errors
- [ ] Professional email and LinkedIn URL
- [ ] Updated GitHub with clean, documented projects

**Interview Prep**:
- [ ] 50+ easy, 30+ medium, 10+ hard problems solved
- [ ] Common patterns practiced (two pointers, sliding window, DP, etc.)
- [ ] 8-10 behavioral stories prepared using STAR method
- [ ] System design fundamentals (for mid/senior roles)
- [ ] Company research completed
- [ ] 5-7 questions prepared for interviewer
- [ ] Mock interviews completed
- [ ] Technical setup tested (camera, mic, internet)

**During Interview**:
- [ ] Listen carefully and ask clarifying questions
- [ ] Think out loud and communicate approach
- [ ] Write clean, readable code
- [ ] Test code with examples and edge cases
- [ ] Stay calm if stuck, ask for hints
- [ ] Be honest about what you don't know
- [ ] Show enthusiasm for the role and company

**After Interview**:
- [ ] Send thank-you email within 24 hours
- [ ] Follow up politely if no response in 1 week
- [ ] Continue interviewing elsewhere
- [ ] Negotiate offers professionally with data
- [ ] Accept graciously and confirm details in writing

Good luck with your interviews! 🎯
