## Pisanie CV

### Kluczowe Zasady

1. **Zwięzłość**: 1-2 strony maksymalnie
2. **Ukierunkowanie**: Dostosuj do każdej aplikacji
3. **Kwantyfikuj**: Używaj liczb i metryk
4. **Czasowniki akcji**: Zacznij punkty od silnych czasowników
5. **Format STAR**: Sytuacja-Zadanie-Działanie-Rezultat

### Czasowniki Akcji

**Przywództwo**: Poprowadził, Koordynował, Nadzorował, Zainicjował
**Osiągnięcia**: Osiągnął, Poprawił, Zwiększył, Zredukował
**Techniczne**: Zaprojektował, Zbudował, Zaimplementował, Rozwinął
**Analiza**: Analizował, Oceniał, Diagnozował, Optymalizował

### Kwantyfikowanie Wpływu

**Złe vs Dobre Przykłady**:
```
❌ Poprawił wydajność aplikacji
✅ Poprawił wydajność aplikacji o 40%, redukując czas ładowania z 3.2s do 1.9s

❌ Prowadził zespół deweloperów
✅ Prowadził zespół 5 deweloperów dostarczając 3 główne funkcjonalności w Q2 2024

❌ Zredukował błędy w produkcji
✅ Zredukował błędy produkcyjne o 60% (z 50 do 20/miesiąc) przez automatyczne testowanie
```

### Format STAR dla Osiągnięć

```
Przykład:
"Przeprojektował system płatności (Sytuacja) aby obsłużyć ruch Black Friday
(Zadanie) implementując distributed caching i horizontal scaling (Działanie),
wspierając 10K transakcji/sekundę z 99.99% uptime (Rezultat)"
```

## Sekcje CV

### 1. Nagłówek

**Zawieraj**:
- Imię i nazwisko (większa czcionka, pogrubione)
- Numer telefonu
- Profesjonalny email
- LinkedIn URL
- GitHub URL
- Lokalizacja (Miasto - bez pełnego adresu)

### 2. Umiejętności

**Organizacja według Kategorii**:
```
Języki: JavaScript, TypeScript, Python, Java, C#, SQL
Frontend: React, Redux, Next.js, Vue.js, HTML5, CSS3
Backend: Node.js, Django, Spring Boot, .NET
Bazy Danych: PostgreSQL, MongoDB, Redis
DevOps: Docker, Kubernetes, AWS, CI/CD
```

### 3. Doświadczenie Zawodowe

**Format**:
```
Stanowisko | Firma | Lokalizacja | Daty

- Osiągnięcie z kwantyfikacją rezultatu
- Kolejne osiągnięcie z metrykami
- Użyte technologie i wpływ na biznes
```

### 4. Edukacja

**Zawieraj**:
- Stopień naukowy i kierunek
- Uczelnia
- Rok ukończenia (opcjonalnie GPA jeśli >3.5)

### 5. Projekty (dla juniorów lub częste zmiany pracy)

**Format**:
```
Nazwa Projektu | Technologie | Link

- Problem rozwiązany przez projekt
- Twój wkład i użyte technologie
- Rezultat (użytkownicy, wydajność, itp.)
```

## Przygotowanie do Rozmowy

### 3-Miesięczny Plan Przygotowań

**Miesiąc 1: Fundamenty**
- Tydzień 1: Data Structures (Arrays, LinkedLists, Stacks, Queues)
- Tydzień 2: Trees & Graphs (BST, BFS, DFS)
- Tydzień 3: Hash Maps & Sets
- Tydzień 4: Sortowanie i Binary Search

**Miesiąc 2: Algorytmy**
- Tydzień 1: Two Pointers, Sliding Window
- Tydzień 2: Recursion & Backtracking
- Tydzień 3: Dynamic Programming Basics
- Tydzień 4: Greedy Algorithms

**Miesiąc 3: System Design & Practice**
- Tydzień 1-2: System Design Basics
- Tydzień 3: Mock Interviews
- Tydzień 4: Pytania Behawioralne & Finalne Przygotowanie

### Zalecane Zasoby

**Platformy Praktyczne**:
- LeetCode (Easy → Medium → Hard)
- HackerRank
- CodeSignal
- AlgoExpert

**Książki**:
- "Cracking the Coding Interview" - Gayle McDowell
- "System Design Interview" - Alex Xu
- "Elements of Programming Interviews" - Aziz, Prakash, Lee

**System Design**:
- Grokking the System Design Interview
- System Design Primer (GitHub)

## Best Practices Rozmów

### Rozmowy Techniczne

1. **Wyjaśnij Problem**: Zadawaj pytania, potwierdzaj zrozumienie
2. **Myśl Na Głos**: Komunikuj proces myślowy
3. **Zacznij od Prostego**: Brute force → Optymalizacja
4. **Testuj Podczas Pisania**: Nie czekaj do końca
5. **Zarządzaj Czasem**: 45 minut - planuj zgodnie z tym

### Rozmowy Behawioralne

**Przygotuj 8-10 Historii** używając STAR:
- Przywództwo / Inicjatywa
- Konflikt / Niezgoda
- Porażka / Lekcja
- Sukces / Osiągnięcie
- Nauka Nowej Technologii
- Praca Pod Presją
- Mentoring / Pomoc Innym

### Często Zadawane Pytania Behawioralne

1. Opowiedz o sobie
2. Dlaczego ta firma?
3. Dlaczego zmieniasz pracę?
4. Opowiedz o trudnym problemie technicznym
5. Opisz konflikt z członkiem zespołu
6. Jak radzisz sobie z ciasnymi terminami?
7. Jak się uczysz nowych technologii?
8. Opowiedz o porażce
9. Gdzie widzisz siebie za 5 lat?
10. Jakie masz pytania do nas?

## Negocjacje

### Badanie Wynagrodzenia

**Źródła**:
- Levels.fyi (tech companies)
- Glassdoor
- Payscale
- Blind (app for verified employees)
- H1B Salary Database

### Taktyki Negocjacyjne

1. **Nigdy Nie Podawaj Pierwszej Liczby**: Zapytaj o zakres
2. **Zbieraj Wiele Ofert**: Leverage dla negocjacji
3. **Negocjuj Wszystko**: Wynagrodzenie, bonusy, equity, benefity
4. **Bądź Przygotowany do Odejścia**: Znaj swoją minimalną akceptowalną ofertę
5. **Dostań To Na Piśmie**: Ustne obietnice nie liczą się

### Email Template Negocjacyjny

```
Temat: Re: Oferta Stanowiska [Nazwa]

Szanowny/a [Imię],

Dziękuję za ofertę na stanowisko [Nazwa]. Jestem podekscytowany możliwością
dołączenia do [Firma] i wniesienia wkładu do [konkretny projekt/team].

Po przejrzeniu oferty i biorąc pod uwagę moje doświadczenie w [konkretne 
umiejętności], a także badanie rynku dla tej roli, zastanawiam się czy
możliwe jest zwiększenie wynagrodzenia podstawowego do [liczba].

[Opcjonalnie: Dodaj kontekst - inne oferty, unikalny wartość]

Jestem otwarty na dyskusję i cieszę się na współpracę.

Pozdrawiam,
[Twoje Imię]
```

### Ewaluacja Oferty

**Rozważ**:
- Wynagrodzenie podstawowe
- Bonus roczny
- Equity/Stock options
- Benefity (ubezpieczenie, emerytura)
- Work-life balance
- Możliwości rozwoju
- Kultura firmy
- Lokalizacja / Remote work
- Team i manager

**Red Flags**:
- Odmowa podania zakresu wynagrodzenia
- Presja na szybką decyzję
- Brak jasnych oczekiwań roli
- Wysoką rotację pracowników
- Słabe opinie online

## Pytania Do Zadania Podczas Rozmowy

### O Roli
1. Jak wygląda typowy dzień na tym stanowisku?
2. Jakie są największe wyzwania tej roli?
3. Jak wygląda success po 3/6/12 miesiącach?
4. Z jakimi zespołami będę współpracować?

### O Zespole
1. Jak duży jest zespół?
2. Jaki jest tech stack?
3. Jak wygląda proces code review?
4. Jak podejmujecie decyzje techniczne?

### O Firmie
1. Jak firma wspiera rozwój pracowników?
2. Jakie są możliwości awansu?
3. Jak wygląda work-life balance?
4. Jak firma radzi sobie z remote work?

### O Projekcie
1. Nad czym będę pracować pierwszych kilka miesięcy?
2. Jak mierzycie sukces projektu?
3. Jaki jest największy technical challenge teraz?
